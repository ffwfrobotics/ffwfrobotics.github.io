    Writing an extension¶

    An extension is a module that adds hooks, tools, commands and options to a session. These are the contract it implements and the handles its hooks are given.

    Names: Agents, Attachments, Basis, CURSOR_POINTS, CallDraft, Compaction, Count, CountJob, Counter, CounterAnswer, Cursor, CursorHook, CursorId, DefinitionError, Extension, Form, LabelName, Model, NodeHandle, NodeId, Permissions, Prune, RequestCount, Skills, StepLimit, Subject, TOOL_POINTS, ToolHook, TreeHandle, Usage

    CallDraft¶

    class CallDraft

    The call a tool hook works on. id and tool are read-only: the call is already named, and an edit to either would be ignored. args_raw and outcome may be set.

    Setting outcome in pre_tool answers the call (the tool does not run, and later pre_tool hooks still see it and may change it); in pre_result it edits the outcome.

    Compaction.post_step¶

    async def post_step(self, cursor: Cursor, subject: Subject) -> None

    The soft limit: when a turn ends (a step that came to a reply with no calls, the cursor coming to rest), compact if the branch is past it. A turn that is still going on is left alone until the hard limit. Only a step that committed the reply itself counts: going back to a reply, or a cursor opened on one, ends a step there without a turn.

    Counter¶

    class Counter(Protocol)

    What an extension offers as its counter attribute (at most one extension may). count is synchronous and does no network IO: the driver runs it in a thread. Core keeps every report: an answer for a node a report covers fails the count with a DefinitionError.

    Cursor¶

    class Cursor(TreeHandle)

    What a cursor hook acts through: one cursor, bound to its extension.

    The tree handle, plus the cursor's own move, write, and set_auto, which core allows only while a cursor hook job is out for the cursor. Once the hook coroutine returns (retire), they raise NotInHook; so does every other write and ask. Reads still work. Core checks no more than that the tree stays valid (no hook edit limits).

    Cursor.node¶

    def node(self, id: int | None = None) -> Node

    The node id, or the node this cursor is on when id is None.

    Cursor.walk¶

    def walk(self) -> list[Node]

    The nodes from the root to the node this cursor is on.

    Cursor.options¶

    def options(self) -> Any

    This extension's options at the cursor's at (its options dataclass); raises ConfigError if it has none or what is set does not fit.

    Cursor.options_of¶

    def options_of(self, extension: str) -> Any

    Another extension's options at the cursor's at, as options reads its own; ConfigError if it has none (it is not loaded, or declares no options).

    Cursor.models¶

    def models(self) -> tuple[str, ...]

    The qualified names of the models the catalog defines, in file order: what set_model accepts.

    Cursor.tools¶

    def tools(self) -> tuple[str, ...]

    The names of the driver's tools, the extensions' included, in the order a sample is offered them: the names a pre_sample hook may put in Subject.tools.

    Cursor.show¶

    def show(self, text: str | None) -> None

    Show text on this cursor to every client, as this extension's one line (CursorView.shown); a later call replaces it, and None shows nothing. It is not in the log or the scratchpad: it is gone when the session is reloaded, and dropped when the cursor closes. TypeError for anything else.

    Cursor.set_model¶

    def set_model(self, model: Model) -> int

    Write a Config node under at that sets the branch's model (a qualified name) and move onto it, as write does. ConfigError if it is not configured; nothing is written then. Returns the new node's id.

    Cursor.set_options¶

    def set_options(self, **changes: object) -> int

    Write a Config node under at that sets these options of this extension (JSON values) and move onto it, as write does: each replaces the walk's earlier value. ConfigError if the extension has no options, or those that result, folded with the walk's, do not fit its options type (a __post_init__ that raises refuses); nothing is written then. Returns the new node's id.

    Cursor.save_options¶

    def save_options(self, **changes: object) -> None

    Write these options of this extension (JSON values) into the user's config file, extensions.<name> in <TAU_HOME>/config.json, and have the driver read it at once. The file is every session's and every branch's; set_options is this branch's, a node. No node is written and nothing moves. The project's config is never written. ConfigError if the extension has no options, the options that result (the layers, with these) do not fit its options type, or the driver was given no user config; nothing is written then.

    The file is read, changed and written back with no await in between, so on the event loop (a hook, a tool, an async command) saves cannot interleave. It is not safe against another τ process saving at the same moment (the last write wins, losing the other's change), nor from sync commands that save at once on worker threads.

    Cursor.saved_options¶

    def saved_options(self) -> Mapping[str, object]

    What the user's config file itself sets of this extension's options, as JSON values ({} if it sets none, or there is no file): the value save_options changes, not options(), which folds the project's layer, the overrides and this branch's nodes in. To add to a list option in the file, read it here, not there. ConfigError if the extension has no options or the driver was given no user config.

    Cursor.move¶

    def move(self, to: int) -> None

    Move to to at once; later hooks see the new at. Raises NoSuchNode.

    Cursor.write¶

    def write(
    self,
    body: Body,
    delivers: Sequence[int] = (),
    *,
    copied_from: int | None = None,
    derived_from: int | None = None,

    Append body under at and move onto it, as one record; the delivers items are removed. Returns the new node's id. copied_from and derived_from as for TreeHandle.append.

    Cursor.set_auto¶

    def set_auto(self, on: bool) -> None

    Turn this cursor's auto-step on or off. Wakes nothing: the step is running. Turning it on inside a step that is aborted leaves the cursor at rest.

    Cursor.tell¶

    def tell(self, text: str, *, to: str | None = None) -> None

    Send text as a Notice to client to, or to every connected client by default. Dropped if to is not connected: a notice is for someone who is there.

    Cursor.ask¶

    async def ask(self, text: str, expect: object = str, *, to: str | None = None) -> Any

    Ask the cursor's clients text, and wait for an answer of type expect (any hint of the type language; str by default). Returns the checked, converted answer, or None if declined. to names the client asked first (None: anyone; a client that is not connected is the same). The hook's job stays out meanwhile, however long and whoever is connected, so the cursor is busy; an abort or go-to declines it (and any asked later in that step). A CursorId answer of "new" opens a cursor at the cursor's at.

    DefinitionError¶

    class DefinitionError(TypeError)

    A tool, command, extension or question that cannot be built: a parameter with no annotation or one outside the type language, a default that does not fit its hint, an injected parameter the function cannot have, a name taken twice, or an object that breaks the Tool or Extension contract. The message names the extension, function and parameter.

    Extension¶

    class Extension(Protocol)

    Hooks are methods named for their hook point, found by name and all optional.

    Cursor hooks (CursorHook): pre_step, pre_input, pre_sample, pre_reply, post_reply, post_result, post_step. Tool hooks (ToolHook): pre_tool, pre_result. name is non-empty and unique among a driver's extensions; any attribute named pre_* or post_* that is not a hook point is refused when the driver is built (DefinitionError), so a misspelt hook cannot sit silent. That covers data too: a dataclass field pre_prompt is refused. Name such a field for what it holds (prompt_prefix, before_prompt), never with those two prefixes.

    Optional attributes besides the hooks: tools, commands, options, yields_names, and rescan (Rescanning).

    Extension.name¶

    property name: str

    The extension's name: letters, digits, _ and -, unique among a driver's extensions.

    Form¶

    @dataclass(frozen=True)
class Form
    name: str
    description: str
    schema: Json
    extension: str | None = None
    yields: bool = False

    What a client knows of something it fills in: a command (its name, typed as /name, its description and the schema of its arguments, with the named types' "format" and each default, and the extension that owns it) or an extension's options (the name of the extension, and a schema whose defaults are the values now; extension is None, as it is for /config). A command is called by its qualified name, extension:name, which on the wire a client writes itself from the two fields. A command that yields gives its bare name up to any other command that has it (/model stays the built-in's; the yielding one is only /skills:model). Frozen, compared by value, and not hashable: the schema is a dict.

    Form.qualified¶

    property qualified: str

    extension:name for a command, which nothing can take the name of; name for a form with no extension.

    RequestCount¶

    @dataclass(frozen=True)
class RequestCount
    total: Count
    base: Count
    base_nodes: int
    nodes: Mapping[int, Count]
    why: str | None = None

    What the walk to a node will cost as a request (Cursor.count).

    total is the whole request. base counts the walk's first base_nodes nodes and the request's overhead (tool definitions, hidden prompts, per-message overhead) as one; it is NONE with base_nodes 0 while no reply on the walk has reported its usage. nodes has one count for each node that is sent, by node id, except a node inside a lump: where two requests prove that the nodes between them cost a known sum, the first node holds the sum and the others have no count of their own, so a cut never lands inside one. why says why the total is weaker than it could be, or is None.

    StepLimit¶

    class StepLimit
    name = 'step_limit'
    options = Options

    Turns a cursor's auto-step off after limit unattended steps in a row (D1).

    The limit is the extension's option (Options.limit, 50 unless configured), read at each hook, so /config step_limit changes it for a branch.

    It guards the loops where the cursor does move every step, such as a model that calls tools forever or a hook that writes "continue" after every reply. A cursor that does not move is stopped by core, not by this limit.

    The count is this object's own memory, per cursor, kept at hook points:

    • pre_input sets it to 1: the step that takes an input is the first. There is no post_input hook; pre_input fires once per input item offered.
    • pre_step adds one, when the cursor's auto-step is on. A step run with auto-step off (a frontend's step, a load) is attended and is not counted.
    • post_step turns auto-step off when the count has reached limit, and starts the count over, so whoever resumes the cursor (set_auto) gets another limit steps. It also starts over whenever it sees auto-step off: a halt, an abort, or a go-to ended the run.

    When core turns auto-step off because a step did not move the cursor, that happens after post_step: the count stays as it was until the next input.

    A hook that leaves an input pending offers it again every step, so pre_input restarts the count every time: this limit does not bound that. List it after any extension that turns auto-step back on from post_step, or that hook's set_auto(True) wins.

    Subject¶

    @dataclass
class Subject
    draft: Draft | None = None
    node: Node | None = None
    ending: Ending | None = None
    tools: Sequence[str] | None = None

    The mutable thing a cursor hook works on, by hook point.

    draft for pre_input, pre_sample, pre_reply (a hook may replace it; from pre_sample it is a reply that answers the sample). node for post_reply and post_result. ending for post_step. pre_step has none.

    tools is for pre_sample alone: the names of the tools this one sample is offered, or None (the start) for all of them. What the hooks leave in it is the offer; the next sample starts at None again. A name that is not one of the driver's tools, or any tools set at another point, fails the step as a hook that breaks its contract does.

    TreeHandle.rest¶

    async def rest(self, cursor: int) -> Ending | None

    Wait until cursor is at rest with no effect out, and return how its last step ended; None if that is not known (it has not stepped since the session was loaded). After a send to a cursor that was at rest, this is the ending of the step the send caused. If the cursor was mid-step, the input waits for that step to end and this may return that earlier step's ending with the input still pending: to wait for the step a send causes, rest first, then send, then rest again. A cursor held by an open question or a gate does not rest, so this waits as long as the cursor is held. Async only: a sync tool, which runs on a worker thread, cannot call it. ValueError for this handle's own cursor: waiting for itself would never end. No cycle between two cursors is detected; the user's abort is the way out: when this handle's own cursor is aborted (or sent elsewhere) while the wait is out, the wait ends at once and returns Ending.Aborted(), so a hook, which an abort never cancels, learns it was aborted. The cursor waited on is left as it is.

    TreeHandle.abort¶

    def abort(self, cursor: int) -> None

    Abort cursor's step as a client's abort does: cancel its sample or calls, stop its command, decline its open questions, and turn its auto-step off. Safe from a sync tool's worker thread: it returns once the event loop has done it. ValueError for this handle's own cursor: aborting it would cancel this very call.

    TreeHandle.close_cursor¶

    async def close_cursor(self, cursor: int) -> None

    Close cursor: abort its step as abort does, wait for it to rest, drop its pending items, and close it (D17). It leaves cursors() and the clients' views; its id, its last node (in closed()) and its labels stay, which is what reopen restarts from. Anyone waiting on it sees the abort. CursorClosed if it is already closed. Async only, like rest. ValueError for this handle's own cursor: closing it would wait on itself.
